# 🍔 Hamburger POS Register System

ハンバーガーショップ向けに開発した、ブラウザ完結型のPOSレジシステムです。

レジでの注文受付・現金会計から、キッチンでの調理状況管理、注文番号の表示、売上集計まで、店舗運営に必要な基本機能を4つの画面で構成しています。

Firebase Firestoreを利用することで、レジ・キッチン・店頭ディスプレイ間で注文情報をリアルタイムに共有します。

https://hamburger-pos-regi.vercel.app/pos

## 📸 主な機能

### 1. POSレジ画面（POSPage.jsx）

レジスタッフが注文を受け付け、会計を行う画面です。

- **商品選択**
  - ハンバーガー・サイドメニュー・ドリンクのカテゴリー別表示
  - 商品画像と価格を表示
- **商品オプション**
  - 商品ごとのオプション選択
  - 単一選択・複数選択に対応
  - オプションによる追加料金の計算
- **注文管理**
  - カートへの商品追加
  - 商品数量の変更
  - 注文済み商品の編集・削除
  - 商品ごとの小計と注文全体の合計金額を自動計算
- **現金会計**
  - テンキーによる預かり金額の入力
  - お釣りの自動計算
  - 合計金額に満たない場合は会計を確定できない仕組み
- **注文確定**
  - Firestoreへの注文データ保存
  - 注文番号の発行
  - レシート形式の会計結果表示

### 2. キッチン画面（kitchen.jsx）

調理スタッフが注文内容と調理状況を管理する画面です。

- **リアルタイム注文取得**
  - Firestoreの注文データをリアルタイム監視
  - 新しい注文を自動的に画面へ反映
- **調理状況管理**
  - 注文内の商品ごとに調理完了状態を切り替え
  - すべての商品が完成すると「準備OK」ボタンが有効化
  - 注文全体のステータスを `ready` に更新
- **受け渡し管理**
  - 準備完了した注文を「お渡し待ち」に表示
  - 受け渡し完了後、ステータスを `completed` に更新
- **注文キャンセル**
  - 確認ダイアログによるキャンセル処理
  - ステータスを `cancelled` に更新
- **注文履歴**
  - 完了・キャンセル済みの注文を一覧表示
  - 注文日時の降順で表示

### 3. オーダー表示画面（display.jsx）

店頭などに設置し、お客様が注文状況を確認するための画面です。

- Firestoreから注文情報をリアルタイム取得
- 注文をステータスごとに分類
  - **オーダー**：調理中の注文（`pending`）
  - **未会計**：調理が完了し、お渡し待ちの注文（`ready`）
- 注文番号を3桁で表示
- 古い注文から順番に表示
- キッチン側で状態が更新されると表示も自動更新

### 4. 売上管理画面（sales.jsx）

店舗の売上状況を確認・集計する画面です。

- **期間別集計**
  - 日別・月別の切り替え
  - 日付・対象月の指定
- **売上サマリー**
  - 売上合計
  - 会計済み注文数
  - 客単価
  - キャンセル件数
- **商品別集計**
  - 商品ごとの販売数量
  - 商品ごとの売上金額
- **CSV出力**
  - 集計結果の商品別データをCSV形式でダウンロード
  - Excelで日本語を扱いやすいようUTF-8 BOMを付与

## 🔥 Firebase / Firestore

注文データはFirestoreの `orders` コレクションに保存します。

### 注文データの主な構成

```js
{
  items: [
    {
      productId: "商品ID",
      name: "チーズバーガー",
      price: 220,
      quantity: 1,
      totalPrice: 220,
      selectedOptions: [],
      optionLabels: [],
      kitchenDisplayString: "チーズバーガー",
      isCompleted: false
    }
  ],
  totalPrice: 220,
  cashReceived: 500,
  changeAmount: 280,
  status: "pending",
  orderNumber: 123,
  createdAt: serverTimestamp()
}
```

### 注文ステータス

| ステータス  | 内容                 |
| ----------- | -------------------- |
| `pending`   | 注文受付済み・調理中 |
| `ready`     | 調理完了・お渡し待ち |
| `completed` | 受け渡し完了         |
| `cancelled` | キャンセル           |

キッチン画面で商品の調理完了状態を管理し、注文全体の状態を更新します。

## 🧮 処理の共通化

価格計算や売上集計など、複数の画面で使用する処理はユーティリティファイルに分離しています。

| ファイル       | 主な役割                                     |
| -------------- | -------------------------------------------- |
| `price.js`     | 商品オプションを含めた価格計算・注文合計計算 |
| `sales.js`     | 売上サマリー・商品別売上集計                 |
| `csv.js`       | 商品別売上データのCSV変換                    |
| `dateRange.js` | 日別・月別の集計期間の取得                   |

## 💡 開発上のポイント

- **リアルタイム同期**：Firestoreの `onSnapshot` を利用し、レジ・キッチン・オーダー表示画面で注文情報を共有。
- **画面ごとの役割分担**：注文受付、調理管理、注文番号表示、売上管理を独立した画面として構成。
- **商品オプションの柔軟な管理**：単一選択・複数選択・追加料金に対応。
- **処理の共通化**：価格計算や売上集計などをユーティリティに分離し、画面側の処理を整理。
- **CSS Modules**：画面ごとにCSSを分離し、スタイルの干渉を防止。

## ⚠️ 現在の仕様・注意点

- 会計処理は現金を想定した実装です。クレジットカードや電子マネーなどの決済端末との連携は含みません。
- 注文番号は3桁の乱数で発行するため、同じ番号が重複する可能性があります。
- Firestoreのセキュリティルールや認証設定は、実際の店舗運用に合わせて別途設定する必要があります。
- 売上集計はFirestoreに保存された注文データをもとに行います。

## 🎯 開発目的

実店舗のハンバーガーショップで使用するPOSシステムを想定し、注文受付から調理・受け渡し・売上管理までの一連の流れをWebアプリケーションとして構築しました。

単なる注文フォームではなく、複数の画面がFirestoreを通じて連携する仕組みを実装することで、店舗業務を想定したシステム開発に取り組んでいます。
